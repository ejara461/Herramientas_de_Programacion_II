Lectura 1 — Recordando la arquitectura cliente-servidor-BD

Desde la Clase 1 venimos trabajando con tres piezas: el cliente (el navegador, que muestra HTML y recibe lo que el usuario escribe), el servidor (donde corre PHP, que procesa la lógica) y, a partir de hoy, la base de datos (MySQL, donde los datos quedan guardados de forma permanente, no solo mientras la página está abierta). Hasta la Clase 4, tus variables PHP vivían y morían en cada carga de página. Hoy esos datos empiezan a vivir en una base de datos: sobreviven aunque cierres el navegador o apagues el computador.

Lectura 2 — La cadena de conexión: cuatro datos para hablar con MySQL

Para que PHP se conecte a una base de datos MySQL necesita cuatro datos: el servidor (normalmente "localhost" cuando trabajas en tu propio equipo con XAMPP), el usuario de MySQL (por defecto "root" en XAMPP), la contraseña (por defecto una cadena vacía "" en XAMPP) y el nombre de la base de datos a la que te quieres conectar (la tuya, por ejemplo "practica_jacobo"). Estos cuatro datos juntos se conocen como la cadena de conexión, aunque en PHP no se escriben como una sola cadena de texto sino como cuatro argumentos separados.

Lectura 3 — mysqli_connect(): abriendo la conexión

$conexion = mysqli_connect("localhost", "root", "", "practica_jacobo");

if (!$conexion) {
    die("Error de conexión: " . mysqli_connect_error());
}

mysqli_connect() recibe los cuatro datos de la Lectura 2, en ese orden exacto: servidor, usuario, contraseña, base de datos. Si la conexión falla (por ejemplo, si el nombre de la base de datos está mal escrito, o el servidor de MySQL no está encendido), la función devuelve false en vez de una conexión válida. Por eso siempre se valida el resultado con un if: si $conexion es falso, se usa mysqli_connect_error() para obtener el mensaje exacto de qué salió mal, y die() detiene la ejecución del script ahí mismo, mostrando ese mensaje en vez de seguir con errores en cadena más abajo.

Lectura 4 — mysqli_query(): enviando una instrucción SQL

$sql = "SELECT * FROM contactos WHERE categoria = 'familia'";
$resultado = mysqli_query($conexion, $sql);

mysqli_query() recibe dos argumentos: la conexión ya abierta y una cadena de texto con la instrucción SQL que quieres ejecutar. Para un SELECT exitoso, no devuelve los datos directamente: devuelve un resultado (técnicamente un objeto mysqli_result), que es como una caja que contiene las filas encontradas, lista para recorrer con otra función. Si la consulta falla (por ejemplo, si el nombre de la tabla o de una columna está mal escrito), mysqli_query() devuelve false.

Lectura 5 — La cláusula WHERE: filtrando filas

Sin WHERE, un SELECT * FROM contactos trae todas las filas de la tabla. Agregar WHERE categoria = 'familia' le dice a MySQL que solo devuelva las filas donde la columna categoria sea exactamente igual a 'familia'. El valor de texto va entre comillas simples dentro de la cadena SQL. También se pueden usar comparaciones numéricas, como WHERE stock < 10 para traer solo los productos con poco inventario.

Lectura 6 — mysqli_num_rows(): cuántas filas trajo la consulta

$total = mysqli_num_rows($resultado);
echo "Se encontraron " . $total . " registros.";

mysqli_num_rows() recibe el resultado devuelto por mysqli_query() y devuelve un número entero: cuántas filas coinciden con la consulta. Es útil para saber si una búsqueda encontró algo antes de intentar mostrarlo, o simplemente para reportar un total.

Lectura 7 — mysqli_fetch_assoc(): trayendo un registro

$fila = mysqli_fetch_assoc($resultado);
echo $fila["nombreContacto"];
echo $fila["telefono"];

mysqli_fetch_assoc() toma una fila del resultado y la devuelve como un arreglo asociativo: cada columna de la tabla se convierte en una llave del arreglo, con el mismo nombre de la columna. Así, $fila["nombreContacto"] accede al valor de esa columna en esa fila.

Hoy trabajamos con un solo registro por consulta (una fila), así que basta con llamar mysqli_fetch_assoc() una vez. Cuando en la Clase 6 veamos bucles, podremos llamar esta función repetidamente dentro de un while para recorrer todas las filas de un resultado con varios registros — eso todavía no lo hacemos hoy.
