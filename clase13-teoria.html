Clase 13 · Expresiones regulares y validación de formato

preg_match(), patrones básicos, validación en el servidor y atributo pattern en el navegador — 1:00 p. m. a 5:30 p. m.

Parte 1 — Validar el formato, no solo que no esté vacío

Lectura 1 — Lo que trim() no detecta

Desde la Clase 8 tus formularios revisan que ningún campo llegue vacío con trim(). Esa revisión no basta: en el campo de teléfono se puede escribir hola, en un precio 12abc y en un nombre #$%. Ninguno está vacío, así que pasan, y la base de datos se llena de datos que no sirven.

Además, (int) y (float) esconden el error: (float)"12abc" da 12 sin avisar. El dato se guarda mal y nadie se entera. Hoy aprendes a revisar el formato del dato antes de guardarlo: qué caracteres puede tener y cuántos.

Lectura 2 — Qué es una expresión regular y preg_match()

Una expresión regular es un patrón que describe cómo debe verse un texto: por ejemplo, "un 3 seguido de 9 dígitos". En PHP se comprueba con preg_match(patrón, texto), que devuelve 1 si el texto cumple el patrón y 0 si no lo cumple.

$patron = '/^[0-9]+$/';            // solo dígitos, uno o más
echo preg_match($patron, "180000");  // 1: cumple
echo preg_match($patron, "12abc");   // 0: tiene letras

El patrón se escribe entre comillas simples. Dentro de comillas dobles PHP intenta leer cualquier $ como el inicio de una variable, y los patrones usan el $ con otro significado (Lectura 3).

Ejercicio interactivo

¿Qué devuelve preg_match('/^[0-9]+$/', "95000")?

Parte 2 — La sintaxis básica

Lectura 3 — Delimitadores y anclas: / /, ^ y $

El patrón va entre dos barras / /, que se llaman delimitadores. Dentro, ^ significa "aquí empieza el texto" y $ significa "aquí termina el texto". Juntos obligan a revisar el texto completo.

echo preg_match('/3[0-9]{9}/', "abc3001234567xyz");    // 1: lo encontró dentro
echo preg_match('/^3[0-9]{9}$/', "abc3001234567xyz");  // 0: el texto completo no lo es

Sin ^ y $, preg_match() solo busca si el patrón aparece en alguna parte, y la basura de los lados pasa. Para validar un campo, el patrón siempre lleva ^ al inicio y $ al final.

Ejercicio interactivo

¿Para qué sirven ^ y $ en '/^[0-9]{1,3}$/'?

Lectura 4 — Clases de caracteres: qué caracteres se permiten

Los corchetes [ ] forman una clase de caracteres: representan un carácter, que debe ser uno de los que están dentro. El guion indica un rango.

[0-9]          un dígito (también se escribe \d)
[a-z]          una letra minúscula sin tilde
[A-Z]          una letra mayúscula sin tilde
[a-zA-Z0-9 ]   una letra, un dígito o un espacio (el espacio también cuenta)
[áéíóúÁÉÍÓÚñÑ] una vocal con tilde o una ñ: hay que escribirlas, no están en a-z
3              fuera de corchetes, un carácter fijo: exactamente un 3

Todo lo que no está en la clase queda prohibido: si la clase es [a-zA-Z0-9 ], los signos #, -, ' o < no pasan.

Lectura 5 — Cuantificadores: cuántas veces

Después de un carácter o de una clase se indica cuántas veces puede aparecer:

{9}       exactamente 9 veces
{3,100}   entre 3 y 100 veces
+         una o más veces
*         cero o más veces
?         cero o una vez (lo hace opcional)

Ejemplo completo, el celular colombiano: '/^3[0-9]{9}$/' se lee "empieza, un 3, nueve dígitos, termina". Los celulares en Colombia tienen 10 dígitos y empiezan por 3.

Ejercicio interactivo

Lectura 6 — Tildes y ñ: el modificador u

Cuando el patrón tiene tildes o ñ, se agrega la letra u después de la barra final: '/^[a-zA-ZáéíóúÁÉÍÓÚñÑ ]{3,50}$/u'. Sin la u, PHP no cuenta letras sino bytes, y en el texto cada vocal con tilde o cada ñ ocupa 2 bytes.

echo preg_match('/^[a-zA-ZáéíóúÁÉÍÓÚñÑ ]{3,50}$/', "Jé");   // 1: sin u, "Jé" cuenta como 3 (mal)
echo preg_match('/^[a-zA-ZáéíóúÁÉÍÓÚñÑ ]{3,50}$/u', "Jé");  // 0: con u, "Jé" tiene 2 letras (bien)

Sin la u, los límites de longitud dejan de ser confiables. Regla: si el patrón tiene tildes o ñ, lleva u.

Ejercicio interactivo

¿Por qué el patrón del nombre termina en /u?

Lectura 7 — Una parte opcional: los decimales

Para un precio con hasta dos decimales se necesita decir "dígitos, y si quiere, un punto con 1 o 2 dígitos". Los paréntesis agrupan esa parte y el ? la hace opcional:

$patron = '/^[0-9]+(\.[0-9]{1,2})?$/';
echo preg_match($patron, "95000");     // 1: sin decimales
echo preg_match($patron, "95000.50");  // 1: con 2 decimales
echo preg_match($patron, "95.123");    // 0: 3 decimales
echo preg_match($patron, "-5000");     // 0: el signo menos no está permitido

El punto va con barra invertida, \., porque un punto solo, sin barra, significa "cualquier carácter". El punto es el separador decimal: en el formulario no se escribe el punto de miles.

Parte 3 — Validar en el servidor

Lectura 8 — Dónde va la validación en insertar.php y actualizar.php

La validación de formato va después de revisar que no haya vacíos y antes de escapar y ejecutar el SQL. Los errores se acumulan en una variable con .= (Clase 4): si al final sigue vacía, todo está bien y se guarda; si no, se muestra la lista y no se ejecuta nada.

$errores = "";
if ($equipo === "" || $costo === "") {
    $errores .= "<li>Todos los campos son obligatorios.</li>";
} else {
    if (preg_match('/^[a-zA-Z0-9áéíóúÁÉÍÓÚñÑ ]{3,100}$/u', $equipo) !== 1) {
        $errores .= "<li>Equipo: solo letras, números y espacios, entre 3 y 100 caracteres.</li>";
    }
    if (preg_match('/^[0-9]+(\.[0-9]{1,2})?$/', $costo) !== 1) {
        $errores .= "<li>Costo estimado: solo números, con punto y máximo 2 decimales.</li>";
    }
}
if ($errores === "") {
    // escapar, convertir con (int) o (float) y ejecutar el INSERT o el UPDATE
} else {
    $mensaje = "No se guardó nada. Corrige lo siguiente:<ul>" . $errores . "</ul>";
}

Las mismas reglas van en insertar.php y en actualizar.php: un dato que no se acepta al crear un registro tampoco se debe aceptar al editarlo. El número se revisa como texto, antes de (int) o (float).

Lectura 9 — Validar no reemplaza escapar

La expresión regular y mysqli_real_escape_string() hacen trabajos distintos. La primera decide si el dato tiene sentido (un teléfono con 10 dígitos). La segunda protege la sentencia SQL de comillas y otros caracteres especiales. Un patrón estricto hoy puede ampliarse mañana (por ejemplo, para aceptar un apellido como O'Neil, con comilla), y si se quitó el escape, la consulta queda expuesta.

Regla del curso: en los textos se usan las dos, siempre. Primero se valida el formato; después se escapa y se ejecuta.

Parte 4 — Validar también en el navegador

Lectura 10 — El atributo pattern

HTML puede revisar el formato antes de enviar el formulario con el atributo pattern. Se usa la misma expresión, con tres diferencias: sin las barras / /, sin ^ y $ (el navegador siempre revisa el texto completo) y sin la u.

<label>Equipo:
  <input type="text" name="equipo" required
         pattern="[a-zA-Z0-9áéíóúÁÉÍÓÚñÑ ]{3,100}"
         title="Solo letras, números y espacios, entre 3 y 100 caracteres">
</label>

required no deja enviar el campo vacío (pattern no revisa campos vacíos) y title es el texto de ayuda que muestra el navegador. pattern solo funciona en campos de texto (type="text", type="tel" y similares), no en type="number": para usarlo en un precio, el campo pasa a type="text".

Lectura 11 — pattern no reemplaza a preg_match()

La validación del navegador es una comodidad: avisa el error antes de enviar y ahorra una ida al servidor. Pero la controla quien usa el navegador. Con F12 (Inspeccionar) se puede borrar el pattern o el required, y el formulario se envía igual; también se pueden enviar datos sin usar el formulario.

Por eso la regla es: el servidor valida siempre, con preg_match(), aunque el formulario tenga pattern. Lo mismo pasó con el id del campo oculto en la Clase 12: todo lo que llega del navegador se revisa en PHP.
