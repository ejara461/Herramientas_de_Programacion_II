Clase 14 · Manejo de excepciones con try/catch

mysqli_sql_exception, try/catch, códigos de error, mensaje para el usuario y registro para el desarrollador, conexion.php con require — 1:00 p. m. a 5:30 p. m.

Parte 1 — Cuando la base de datos falla

Lectura 1 — El if (!$conexion) que nunca se ejecutaba

Desde la Clase 5 tus archivos se conectan así: mysqli_connect() y, debajo, if (!$conexion) { die(...) }. La idea era que, si la conexión fallaba, mysqli_connect() devolviera false y el if mostrara el mensaje del die().

Eso era cierto en versiones viejas de PHP. Desde PHP 8.1 (el aula tiene PHP 8.2.12), cuando una función mysqli_* falla no devuelve false: lanza una excepción llamada mysqli_sql_exception. Una excepción es un aviso de error que interrumpe el programa en ese punto. Si nadie la atrapa, PHP se detiene ahí mismo, y el if de la línea siguiente nunca llega a ejecutarse.

Lectura 2 — Lo que ve el usuario cuando nadie atrapa la excepción

Si en tu panel.php cambias la contraseña de mysqli_connect() por una errada, el navegador muestra algo así:

Fatal error: Uncaught mysqli_sql_exception: Access denied for user 'root'@'localhost'
(using password: YES) in C:\...\panel.php:11
Stack trace:
#0 C:\...\panel.php(11): mysqli_connect()

Hay tres problemas. La página se corta a la mitad y el usuario no sabe qué hacer. El mensaje es técnico y en inglés. Y le muestra a cualquiera datos internos de la aplicación: la carpeta donde está el archivo, la línea, el usuario de la base de datos. Esos datos le sirven a alguien que quiera atacar el sistema. Lo mismo pasa con una consulta mal escrita, por ejemplo "You have an error in your SQL syntax".

Ejercicio interactivo

En PHP 8.2 la contraseña de la conexión está errada. ¿Qué pasa con este código?

$conexion = mysqli_connect("localhost", "root", "x", "practica_tablero");
if (!$conexion) {
    die("Error de conexión.");
}

Parte 2 — try y catch

Lectura 3 — Intentar y atrapar

try significa "intenta". Dentro de sus llaves va el código que puede fallar. catch significa "atrapa". Si dentro del try se lanza una excepción, PHP deja de ejecutar el try en esa línea y salta al catch. Si no falla nada, el catch se salta. En ambos casos el programa sigue después del bloque, sin "Fatal error".

try {
    echo "A ";
    mysqli_query($conexion, "SELECT * FROM tabla_que_no_existe");   // falla aquí
    echo "B ";                                                       // no se ejecuta
} catch (mysqli_sql_exception $e) {
    echo "C ";
}
echo "D";
// Se imprime: A C D

Entre los paréntesis del catch se escribe qué tipo de excepción se atrapa (mysqli_sql_exception, la de la base de datos) y el nombre de la variable donde queda guardado el error, por costumbre $e.

Lectura 4 — Pedirle datos al error: getCode() y getMessage()

La variable $e guarda el error atrapado. Con la flecha -> se le pide un dato: $e->getCode() da el número del error y $e->getMessage() da el texto técnico que escribió MariaDB. La flecha es una forma de escribir que verás más en el curso; por ahora basta con saber que le pide un dato al error.

1045   contraseña o usuario de la base errados
1049   la base de datos no existe
1146   la tabla no existe
1054   una columna no existe
1064   error de sintaxis en el SQL
1062   valor repetido en una columna UNIQUE

getCode() devuelve un número entero, así que se compara sin comillas: $e->getCode() === 1062. El texto de getMessage() puede variar un poco entre versiones de MariaDB; el número no cambia.

Ejercicio interactivo

Dentro de un catch, $e->getCode() devuelve 1146. ¿Qué pasó?

Lectura 5 — Un mensaje para el usuario y otro para el desarrollador

En el catch se escriben dos mensajes distintos. Al usuario se le muestra un mensaje claro, en español, que diga qué pasó y qué no se hizo, más el código del error para que pueda reportarlo. El texto técnico no se le muestra: se guarda en el registro de errores del servidor con error_log(), donde solo lo ve el desarrollador.

} catch (mysqli_sql_exception $e) {
    error_log("Error en el INSERT (" . $e->getCode() . "): " . $e->getMessage());
    $mensaje = "No se pudo guardar el registro. No se guardó nada. Código de error: " . $e->getCode() . ".";
}

Dónde queda lo que escribe error_log(): si trabajas con php -S (Opción B del aula), aparece en la terminal de VS Code donde corre el servidor. Con Apache de XAMPP queda en el archivo que indica la directiva error_log, que puedes consultar con phpinfo().

Parte 3 — Aplicarlo en tu mini-CRUD

Lectura 6 — conexion.php: la conexión una sola vez, con require

Tu aplicación se conecta en casi todos los archivos, con las mismas líneas repetidas. Si cambias la contraseña o el nombre de la base, tienes que corregir cada archivo. La solución es escribir la conexión, con su try/catch, en un archivo aparte, conexion.php, y traerlo desde cada página con require "conexion.php";.

<?php
// conexion.php
try {
    $conexion = mysqli_connect("localhost", "root", "", "practica_tablero");
} catch (mysqli_sql_exception $e) {
    error_log("Conexión fallida (" . $e->getCode() . "): " . $e->getMessage());
    echo "<p>No fue posible conectar con la base de datos. Intenta más tarde. Código de error: " . $e->getCode() . ".</p>";
    exit;
}

require pega el contenido del archivo en ese punto, así que $conexion queda lista para usar. Si el archivo no existe, require detiene la página; include, en cambio, solo muestra un aviso y sigue sin conexión. Por eso se usa require. conexion.php no lleva ?> al final: así no se cuela un espacio o un salto de línea que rompa el header() de las páginas que lo incluyen.

Lectura 7 — Qué va dentro del try

Dentro del try va la consulta y todo lo que solo debe pasar si la consulta funcionó: el mensaje "Registro guardado", el header("Location: panel.php?msg=...") y su exit. Si la consulta falla, PHP salta al catch y esas líneas no se ejecutan, así que el usuario nunca ve un aviso de éxito falso.

try {
    mysqli_query($conexion, "DELETE FROM repaso_mantenimientos WHERE id = $id");
    header("Location: panel.php?msg=eliminado");   // solo si el DELETE funcionó
    exit;
} catch (mysqli_sql_exception $e) {
    error_log("Error en el DELETE (" . $e->getCode() . "): " . $e->getMessage());
    echo "<p>No se pudo eliminar el registro. No se eliminó nada. Código de error: " . $e->getCode() . ".</p>";
    exit;
}

Lectura 8 — Errores esperados: el usuario repetido

No todo error es una falla del sistema. En tu registro.php de la Clase 11, la columna con la que se inicia sesión es UNIQUE: si alguien intenta registrar un valor que ya existe, MariaDB lo rechaza con el código 1062. Ese caso se puede reconocer en el catch y explicarle al usuario qué hacer:

} catch (mysqli_sql_exception $e) {
    if ($e->getCode() === 1062) {
        $mensaje = "Ese usuario ya existe. Elige otro.";
    } else {
        error_log("Error en el registro (" . $e->getCode() . "): " . $e->getMessage());
        $mensaje = "No se pudo registrar el usuario. Código de error: " . $e->getCode() . ".";
    }
}

Con esto ya no hace falta el SELECT previo que revisaba si el usuario existía. Ese SELECT y el INSERT son dos pasos, y entre los dos otra persona podría registrar el mismo valor; el UNIQUE de la base es la garantía real. Un detalle: el intento rechazado por 1062 gasta un id, por eso pueden quedar saltos en la numeración, y eso no es un error.

Lectura 9 — La validación y el catch no se reemplazan

La validación de la Clase 13 (trim(), preg_match(), $errores) revisa lo que escribe el usuario: si el formato no cumple, el SQL ni siquiera se intenta. El try/catch atrapa lo que falla en la base de datos aunque el dato sea correcto: el servidor está apagado, la tabla o una columna está mal escrita, el valor está repetido. Una aplicación bien hecha tiene las dos cosas, y también sigue escapando los textos con mysqli_real_escape_string().

Lectura 10 — Para conocer (no se exige): finally y throw

Después del catch se puede agregar un bloque finally, que se ejecuta siempre, haya fallado o no el try. También puedes lanzar tus propias excepciones con throw new Exception("mensaje") y atraparlas con catch (Exception $e). Exception atrapa cualquier excepción, incluida la mysqli_sql_exception. En este curso no se usan en el taller; las verás en cursos más avanzados.

try {
    echo "1 ";
    mysqli_query($conexion, "SELECT * FROM x");   // tabla inexistente
} catch (mysqli_sql_exception $e) {
    echo "2 ";
} finally {
    echo "3";
}
// Se imprime: 1 2 3
