Lectura 1 — Repaso rápido de if/else

En la Clase 3 vimos que if/else permite tomar una decisión entre dos caminos a partir de una condición. Por ejemplo, en Gestión de inventarios se puede preguntar si la cantidad en stock es cero o no, y mostrar "Agotado" o "Disponible". Pero la mayoría de decisiones reales no son de solo dos caminos: tienen tres, cuatro o más resultados posibles.

Ejercicio interactivo

¿Qué imprime este código si $stock = 0;?

if ($stock == 0) {
    echo "Agotado";
} else {
    echo "Disponible";
}

Lectura 2 — El problema de encadenar varios if

Si quisiéramos clasificar el stock de un producto en "Agotado", "Bajo", "Medio" o "Alto" usando solo if y else, tendríamos que anidar varios bloques uno dentro de otro, lo que hace el código difícil de leer. PHP ofrece elseif para encadenar varias condiciones seguidas, evaluadas en orden, sin necesidad de anidar.

Lectura 3 — Sintaxis de elseif

if ($stock == 0) {
    echo "Agotado";
} elseif ($stock < 10) {
    echo "Bajo";
} elseif ($stock < 50) {
    echo "Medio";
} else {
    echo "Alto";
}

PHP evalúa las condiciones en orden y ejecuta el primer bloque cuya condición sea verdadera; si ninguna lo es, ejecuta el else final (opcional). Es importante notar que una vez una condición es verdadera, las siguientes ya no se evalúan.

Ejercicio interactivo

Con el código de la Lectura 3, ¿qué se imprime si $stock = 25;?

Lectura 4 — elseif aplicado a otro proyecto

En Gestión Asistencia y Permisos, un permiso puede estar en estado "pendiente", "aprobado" o "rechazado". Con elseif se puede mostrar un mensaje distinto según el estado, en el mismo orden en que normalmente se piensa el flujo: primero si está pendiente, luego si fue aprobado, y por último si fue rechazado.

Lectura 5 — Cuándo usar switch en vez de elseif

Cuando todas las condiciones comparan la misma variable contra distintos valores exactos (no rangos ni combinaciones), switch suele ser más claro que una cadena larga de elseif. Por ejemplo, clasificar el estado de un permiso ("pendiente", "aprobado", "rechazado") es un caso típico de switch, porque siempre se compara la misma variable $estado contra valores fijos.

Lectura 6 — Sintaxis de switch

switch ($estado) {
    case "pendiente":
        echo "En espera de aprobación";
        break;
    case "aprobado":
        echo "Permiso concedido";
        break;
    case "rechazado":
        echo "Permiso denegado";
        break;
    default:
        echo "Estado desconocido";
}

Cada case compara $estado contra un valor. El default cubre cualquier valor que no coincida con ninguno de los casos anteriores.

Lectura 6.1 — Qué hace realmente break (ampliación)

switch no se detiene solo porque un case coincidió: al encontrar la coincidencia, PHP empieza a ejecutar ese bloque y sigue ejecutando el código de los case siguientes, uno tras otro, hasta encontrar un break o hasta llegar al final del switch. break es la instrucción que le dice a PHP "deja de seguir cayendo a los siguientes case, sal del switch ahora".

Por eso, en el ejemplo de la Lectura 6, si $estado es "pendiente" y el break de ese case no estuviera, PHP seguiría ejecutando el case "aprobado" (imprimiría también "Permiso concedido"), luego "rechazado" ("Permiso denegado"), y por último el default ("Estado desconocido") — los cuatro mensajes seguidos, aunque solo uno era el estado real. A este comportamiento se le llama fallthrough ("caída" de un case al siguiente).

El fallthrough no es un error de sintaxis — PHP lo permite y a veces se usa a propósito, cuando dos valores distintos deben producir la misma respuesta. En Gestión comportamental, una falta "leve" y una falta "moderada" pueden generar el mismo llamado de atención, mientras que una falta "grave" requiere citar al acudiente:

switch ($tipoFalta) {
    case "leve":
    case "moderada":
        echo "Se registra un llamado de atención.";
        break;
    case "grave":
        echo "Se cita al acudiente.";
        break;
    default:
        echo "Tipo de falta no reconocido.";
}

Aquí el case "leve" no lleva break a propósito: si $tipoFalta es "leve", cae al case "moderada" y ejecuta ese mismo mensaje. Es el mismo mecanismo del error anterior, usado aquí de forma intencional. La regla práctica: todo case lleva su break al final, salvo que se quiera explícitamente que continúe al siguiente — y en ese caso conviene dejar un comentario que diga por qué.

Lectura 7 — Operadores de asignación compuestos

Además de =, PHP tiene operadores que combinan una operación con la asignación en un solo paso: +=, -=, *=, /= para números, y .= para concatenar cadenas. Por ejemplo, en Gestión de biblioteca, si $prestamos lleva el conteo de préstamos activos de un libro, $prestamos += 1; es equivalente a $prestamos = $prestamos + 1;, pero más corto y más común en código real.

Lectura 8 — Operadores de asignación con cadenas

El operador .= funciona igual pero para texto. En Gestión comportamental, si se va construyendo un mensaje de observación sobre un estudiante, $observacion .= " Llegó tarde."; agrega ese texto al final de lo que ya tenía $observacion, sin tener que reescribir todo el contenido anterior.

Ejercicio interactivo
